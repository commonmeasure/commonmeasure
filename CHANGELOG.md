## 0.4.10 (8 October 2026)

### Added

- The built-in `valyu` adapter searches Valyu and extracts content from a named URL, declaring `search` and `fetch`. `VALYU_API_KEY` travels only in `x-api-key`; a missing key produces an unavailable result. Search declares the standard 20-result ceiling, passes allowed hosts as source filters and leaves admission to source policy. Per-result USD prices stay in native metadata; each operation's reported total becomes its observed acquisition charge, unknown when absent. Licence rights remain unknown. Answer, DeepResearch and AI content summaries are not requested. The adapter is spec-verified against OpenAPI 2.3.0; recorded replay and live verification require separate retained evidence ([Valyu configuration](https://github.com/commonmeasure/commonmeasure/blob/main/docs/integrate/valyu.md)).

- On Claude Code 2.1.287 or later, which runs plugin mods, the plugin answers Claude Code's own `WebFetch` and `WebSearch` through the edge wherever the plugin's MCP server is connected, so source policy rules on each crossing before it happens and the edge records it, whether or not the agent called `context_fetch` itself. A call the edge refuses or cannot carry is refused with the reason, never fetched natively. Only the edge's own server carries a routed call; a `context_fetch` on any other MCP server or connector is never used. The built-in tool runs, and is recorded after the fact, where the edge's server is not connected, for a `WebSearch` with no search provider configured, on an older Claude Code, and under the hooks `commonmeasure install claude` writes, which do not route. Claude Code's own `WebFetch` and `WebSearch` permission rules, managed ones included, do not apply to a routed call: source policy and the permission for `context_fetch` and `context_search` do, and a headless run needs those tools allowed. The standing nudge now tells the agent that a result or refusal saying it went through Common Measure has no native fallback, instead of naming a Claude Code version ([routed](https://github.com/commonmeasure/commonmeasure/blob/main/plugin/README.md#routed--hooksregisterjs)).
- `install.sh --connect HUB --token TOKEN`, the line the hub's Enrol this machine card prints, takes a machine from nothing to its first evidence on Common Measure Hub. After the install and the reporting consent question it runs `commonmeasure first-run HUB --token TOKEN`, which prints one line per step: it registers every agent host found on the machine as `commonmeasure install <host>` would, connects to the hub under its managed policy (or says it is waiting for the organisation's first policy revision), enrols the directory it runs in for hub reporting, makes one governed fetch, relays, and prints the hub's Fleet evidence address and the local console's. Run it in the project directory whose sessions the hub should see: from your home directory or `/` nothing is enrolled, and the line prints the `commonmeasure enrol` command for a project directory. It never confirms existing history for you, so a directory not enrolled before prints the `commonmeasure enrol … --include-history` command instead. In this release the governed fetch is reported as not made, because the source record has no host word for a fetch the installer makes; without reporting consent the fetch line also names `commonmeasure consent agree`. A step that fails stops the run with exit status 3 and the binary installed. The token goes to the hub and appears in no output or file. `--connect` without `--token`, `--token` without `--connect`, `--connect` with `--update`, and a hub address that is not `https` (or `http` to loopback) exit 2 before anything is downloaded.
- The built-in `peopleinc` adapter, the seventeenth content supply adapter, searches the People Inc Content API and retrieves full article markdown, declaring `search` and `fetch`. The key goes only in the `X-API-Key` request header (`PEOPLEINC_API_KEY`); a missing key produces an unavailable result naming the variable, with no anonymous fallback. A search sends a trimmed question with the limit clamped to 1–5 and declares that ceiling, so a job asking for more records a coverage gap naming both numbers; an empty question, or one longer than 2000 Unicode characters after trimming, is refused before any request. Search results keep the supplier's order, full markdown (no second retrieval is made to obtain it), stable identifier, rank and metadata, and the selection summary stays in the sealed raw response. The supplier's `domain` label rides as metadata and is never used as a policy host: every returned source URL is checked against the source policy. Named-article retrieval sends the exact fully-qualified HTTPS target, with no query, fragment, credentials or non-default port, as a standard URL-encoded query value, trailing slashes unchanged; an invalid target is refused rather than changed to a supposed canonical article, and this route is a provider `fetch` a job's `fetch_target` dispatches, not selectable through `context_fetch`. A description of a licensed corpus is no machine-readable grant: licence and monetary cost stay unknown, distinct from free, and every HTTP 200 from the markdown endpoint is treated as billable. The adapter is fixture- and spec-verified only, over loopback transport through planning, admission and source-record sealing; no live call, supplier key or charge is authorised for it, there is no cache and no automatic retry, and acceptance by the live supplier remains unverified ([People Inc content](https://github.com/commonmeasure/commonmeasure/blob/main/docs/integrate/peopleinc.md)).

### Changed

- The source's terms refuse a mediated fetch in every policy mode on every edge, enrolled or not: a `Content-Signal` or `Content-Usage` statement that disallows AI input, and a licence whose AI-input permission needs a payment or a licence-server token the edge cannot provide. No edge holds a settlement rail yet, so every such licence term refuses. Before, `observe` and `prefer` fetched the page and recorded the term as a breach. `robots.txt`, `Crawl-delay`, unread licences and reporting demands already bound in every mode. The policy mode now governs only the operator's own policy: host lists and access rules, required licences, allowances and caps, and processor verdicts. A source whose licence is unknown remains a breach of a required licence that `observe` and `prefer` record and carry ([fail policy](https://github.com/commonmeasure/commonmeasure/blob/main/docs/FAIL-POLICY.md#6-per-mode-enforcement-identical-recording)).
- A source whose licence demands usage reporting is admitted only when the receiver in `relay.json` is a route to the licence's reporting endpoint: the hub the edge is enrolled with (a receiver on the hub's origin, as `connect` writes it, while the key is not revoked), or the endpoint itself, meaning the URL the relay posts to (the receiver followed by `/events`) equals it. Operators relaying to anything other than their hub or the licence's endpoint now see those sources refused in every policy mode. The refusal says the receiver is neither, names it by origin and digest, names the licence's endpoint and says whether the edge is enrolled. Before, any receiver met the demand, so a receiver that forwarded nowhere took the report and the source's endpoint received nothing ([session evidence](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/session-evidence.md#source-declarations)).
- A licence's payment term is unmet unless the licence says it is free: type `free` or `attribution`, or a `<payment>` with no type that states nothing else. A type RSL 1.0 does not define, a case variant of one it does (`Use`), and a `<payment>` with no type beside an `<amount>`, `<standard>`, `<custom>` or `<accepts>` now refuse in every policy mode, as `purchase` or `use` does; the agent is told the type is one the edge does not recognise, and the record keeps it whole. A licence with several `<payment>` elements refuses if any one needs payment, and the record lists every one (`licences[].terms.payments`); a licence with several usage `<permits>` or `<prohibits>` elements is read with every token of each. Before, only the last usage `<permits>` and the last usage `<prohibits>` of a licence were read: a prohibition in an earlier element was dropped, a priced licence naming AI input in an earlier element was read as not naming it, and a usage permitted only in an earlier element was refused. A licence with no usage `<permits>` covers AI input on its own terms, so its payment and its entry's licence server now refuse as well, whether or not it is restricted to a class of user or a region. A licence silent on usage is a grant only where no licence of the same `<content>` names AI input; where one does, that licence's permission, prohibition or price decides. A licence restricted to a class of user or a region authorises nothing: one that permits AI input by name, or is silent on usage and asks for payment, refuses, and its price is on the record. A licence server refuses whatever the offers, a `<content>` with no `<license>` included. Of the `<content>` entries that match a page, the narrowest govern, whatever their length: one whose scope lies wholly within another's governs alone, so `/ab` governs `/abc` beside `/a*b`, `/p` governs `/page` beside `/*`, and `https://host/a` governs `/a/1` beside `/*`. Entries for the same scope, written twice, in two spellings, with and without a trailing `*` (`/` and `/*`), or as an absolute URL and its path (`https://host/` and `/`), are read as one entry, their licences in document order, and so are overlapping entries neither of which lies within the other, such as `/xy` and `/x*z` for `/xyz`. Before, the longer of two matching entries governed alone even where the shorter lay within it, the later of two entries of one length governed alone, `/*` governed alone over `/`, and an absolute URL governed alone over a relative entry of the same path. A licence whose `<content>` entries matching a page would take more work to choose among than the edge does for one page is not read for that page, and the page is refused in every policy mode, as for any licence the edge cannot read; the work counts every matching entry, absolute URLs included, entries that do not match the page count nothing, and 256 matching entries with patterns of up to 64 octets are always within it. Where one `<content>` holds several licences, the edge takes any whose terms it can meet, whatever order they are written in, with one exception: of two free offers that differ only in a reporting demand the edge cannot meet, the first written is taken, so their order decides whether the page is delivered. The record names the one taken (`licences[].terms.offer`, counted from 1). Every `License:` line in the selected `robots.txt` group is read, each is a licence entry in the record, and the terms of every one bind. Before, an undefined or case-variant type, a `<payment>` with no type beside an amount, terms or payment methods, a priced licence with no usage `<permits>`, a licence whose last `<payment>` was free, and a licence server on a `<content>` with no `<license>` were fetched without payment in every mode, and a second `License:` line was never requested. A licence that permits AI input by name to a class of user or a region, delivered on the previous release when free, now refuses. Two changes admit what the previous release refused: a free or attribution offer beside a priced one in the same `<content>` now admits, whatever the document order, and so does a licence silent on usage beside one that permits only other usages, such as `search`. Because governing overlapping entries are read as one, a free or attribution offer permitting AI input by name beside a priced offer is taken in either document order. For example, `/blog/` offering AI input free beside `/*.pdf$` pricing AI input makes `/blog/a.pdf` available free in either order, provided the free offer's other terms are met; a prohibition of AI input in either governing entry still refuses it. A prohibition of AI input in any licence that governs a page refuses it, whatever another licence permits, by name or by silence, free or priced, in either document order, and whether the two licences are in one `<content>` or in entries read as one. This is stricter than 0.4.9 for one `<content>` holding both: a free licence permitting AI input by name beside a licence prohibiting it delivered the page there and refuses it now. Within one licence a specific permit stands over a broader prohibition (`permits ai-input` beside `prohibits all`), and a prohibition in a licence restricted to a class of user or a region counts ([session evidence](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/session-evidence.md#source-declarations)).
- The operator's recorded agreement with a source binds its reporting duty: where the source policy's `terms` entry for the host sets `requires_reporting`, the crossing carries a telemetry reporting demand ruled as a licence's is, in every policy mode, and met only through the hub the edge is enrolled with. Without that route, or without the operator's reporting consent, the crossing is refused before the request. The record holds the ruling in `declarations.reporting` with `source: operator-agreement` and the agreement's `reference`, and where several demands were ruled, every one in `declarations.reporting_demands`. The policy file's shape is unchanged. Before, `requires_reporting` was recorded and bound nothing.
- The source record's reporting ruling (`declarations.reporting`) names the receiver by origin and a 16-digit SHA-256 digest of the configured value instead of its URL, whose path, query or credentials can hold a key, and records the `route` the demand relied on: `hub` or `licence_endpoint`.
- The source record keeps what the agent was told: every `crossing_refused`, and a `crossing_mediated` that returned the agent an error rather than a page or file, carries `told`, the tool error whole, and a refused search result's record carries the reason the agent read in `told` and the result's position in `told_position`. Neither is projected to Content Telemetry: on an own edge `told` names the operator's own files. The text is the edge's own by construction, so recording it discloses nothing, and a reader can check from the record alone that no value the source set reached the agent ([session evidence](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/session-evidence.md#what-the-agent-was-told)).
- The console's shell, navigation, appearance control, badges, alerts, cards, data tables, buttons, fields and policy read groups now come from the design release Common Measure Hub renders too, vendored in `design-tokens/`, so the two applications are one specification rather than two implementations of a description ([design release](https://github.com/commonmeasure/commonmeasure/blob/main/design-tokens/README.md)).
- Appearance offers Light, Dark and System, the same three choices as the hub; a new visitor is light.
- At 52rem and below the sidebar gives way to a header with a Menu disclosure, as in the hub.
- The release's contrast gate runs once, on the token source, when the CSS is generated; the console no longer carries a contrast test of its own, only the check that its embedded CSS is the vendored release.

### Fixed

- A host's `Crawl-delay` is measured from when the edge's last request to it was answered, not from when that request's turn was taken. The name lookup, the back-off check and signing come between the two, and on a loaded machine they held a request up long enough that the next one reached the host less than the delay after it: as little as 741 ms apart under `Crawl-delay: 1`. This holds for requests made one after another; two MCP servers on one edge whose requests to a host interleave inside the delay can still reach it less than the delay apart.
- Every request sent through the edge's shared HTTP client names the content coding the edge decodes: `Accept-Encoding: gzip`, or `identity` where the response is sealed as the provider served it (search and fetch providers). A request without the field accepts any coding (RFC 9110 §12.5.3), so a server answering `br` or `zstd` made `robots.txt` unreadable and refused every page on the host. A response still coded in something the request did not name is refused, and the refusal says the coding was not requested.
- An inbound header value holding bytes that are not UTF-8 (obs-text, such as a Latin-1 `Content-Disposition`), which RFC 9110 allows, no longer fails the message: `robots.txt` and the page are read. The value is kept as received. A redirect `Location` and a supplier's session id are not read from such a value: the redirect is not followed, and the failure names the header. Other headers, and a reason phrase, are read through a rendering that writes each such byte as `\xHH` and each backslash as `\\`; where the source record keeps such a rendering (`content_usage_header`, and `content_type` on a crossing and in the extractor's record) it is marked `content_usage_header_rendered` or `content_type_rendered`, so it is not mistaken for ASCII text that reads the same. Control bytes other than tab are still refused, and outbound guards are unchanged.
- A `Link` header is read from its bytes, and from every `Link` field of the response. A byte that is not UTF-8 in a parameter the edge does not read, such as `title`, no longer stops a licence being read, and a member that cannot be parsed no longer drops the members after it. A member that names an RSL licence and cannot be read (its target, `rel` or `type` not UTF-8, its target not a URL, a parameter name that is not a token where the member mentions `license` and lacks a `rel` or `type`, or the member not parseable and mentioning `license`) is recorded as an unread licence, which withholds the page in every policy mode, and the licence the page last named stays in the host's cache. Before, a stray member ahead of a licence, or a licence in a second `Link` field, left the page admitted with its licence unknown, and a quote left open made the edge request the wrong URL as the licence.
- A `Link` member naming its licence with `rel*` or `type*` (RFC 8187 encoding) is read as one naming it with `rel` or `type`; one whose `rel*` or `type*` does not decode, where it may name a licence, is an unread licence, and so is one whose `rel` and `rel*`, or `type` and `type*`, disagree about whether it names an RSL licence (RFC 8288 Appendix B.2 step 16 gives the starred value precedence; a parser that does not apply it reads the plain one). A member that cannot be parsed and whose only mention of `license` is escaped (`lic\ense`) is an unread licence too. Before, each left the page admitted with its licence unknown.
- A response whose `Link` header names two different RSL licences has the first read and the second recorded as unread, so the page is withheld in every policy mode until reading both is designed. Before, the second was never requested and the page was admitted under the first. Two members resolving to the same URL are one licence.
- An unread `link-header` licence whose `url` is a rendering of bytes that are not UTF-8 is marked `url_rendered`, so it is not mistaken for ASCII text that reads the same.
- A `context_fetch` refusal, failure or declarations summary no longer repeats text the source chose. A header value (`cf-mitigated`, `Content-Type`, `Content-Encoding`), a `Link` member the edge could not read, a licence's own text and a transport fault in the origin's bytes are named by where they were, and so is an unread licence whose target is not a URL as the URL parser writes it, such as one with spaces in it. An `http` or `https` URL the source chose is shown by its origin and path, its query and fragment as `?…` and `#…` whatever characters they hold; a URL with any other scheme, such as `data:`, is named by position. The source record keeps each value whole. A licence named by a URL whose scheme is not `http` or `https` is unread, and a redirect to one is refused, since the edge requests neither. Before, a licence URL's query, a `data:` licence or redirect target, or a malformed `Link` member reached the agent verbatim, past the injection screen ([text from the source in a result](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/host-integration.md#text-from-the-source-in-a-result)).
- A host name the source chose, such as a redirect's, is cut to 64 characters and marked `…` in `context_fetch` refusals, failures and summaries, as a URL's host already was: in host-policy, back-off, `Crawl-delay` and private-address reasons, in the `Crawl-delay` ruling a summary carries, and in lookup, connection and TLS errors, including each name a certificate presents; a certificate name that is neither a DNS name nor an address is named by position. A run's and a search's host-policy reasons name the host the same way. The source record keeps the whole host in the URL it records beside the sentence, and in a transport fault. A URL the URL parser reads shorter than it was written, such as one with `/../` segments or a percent-encoded host, is shown from its parsed parts, so the cut applies to everything the source wrote; before, such a URL reached the agent whole whatever its length. A redirect to a URL whose host was cut is no longer named as a value that is not a URL ([text from the source in a result](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/host-integration.md#text-from-the-source-in-a-result)).
- A crossing that is refused, in any policy mode, or that fails before a page is delivered, gives the agent no text the source chose: not a redirect's host, path or target, a header value, `robots.txt` or licence text, a certificate name or a transport fault in the peer's words, in `context_fetch` or in a `context_search` result's refusals, which now carry the result's position and the reason and not its URL. Such text is built from one type that the compiler will not build from a source string, so the rule holds for code not yet written; a hop is named by its position and a fault by its kind, and a remedy that needs the host points the operator at the record. The source record keeps every value whole, and its own sentences name the host whole again. The `breach` and `policy` a delivered page carries are the same agent sentences; the summary's cut host (`robots.delay.host`, `redirects[]`) is unchanged ([text from the source in a result](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/host-integration.md#text-from-the-source-in-a-result)).
- A tool named `context_fetch`, `context_search` or `context_status` on an MCP server other than the edge's is recorded as an observed MCP result. Before, the hooks took any such tool for the edge's own and recorded nothing, so a crossing through another server, another mod's tool or a connector of that name was missing from the source record ([observed](https://github.com/commonmeasure/commonmeasure/blob/main/plugin/README.md#observed--hookshooksjson)).
- A redirect's absolute `Location` is recorded as the URL requested, resolved against the URL that redirected, as a relative one already was. A tab inside it no longer appears in the source record.
- A `context_fetch` refusal on one of the source's terms says so: `the source's robots.txt` where its access rule refused the URL or its `Crawl-delay` refused a redirect hop, `the source's terms` for a licence it names, its payment or licence-server term, a content signal or a reporting demand. Before, every refusal but the access rule's ended `(operator policy in <policy.json>)`, so a term the source set, refused in `observe` where the operator's policy refuses nothing, was attributed to the operator. The operator's own rules (host lists, a required licence, the principal's authority, the allowance, a private address the policy could admit) still name the policy; a private address under the floor a service-mode edge holds names nobody, since no policy setting lifts it ([session evidence](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/session-evidence.md#what-the-agent-was-told)).
- Managed enrolment skips the relay offer when `CI` is non-empty, stdin or stdout is not a terminal, or `--no-relay-offer` is set. The installer also defers reporting consent when `CI` is non-empty, printing the command to agree later.
- Moving another home's background relay now names that home, explains that its background reporting stops and asks for explicit agreement, defaulting to no. A failed relay installation reports the retry command and leaves managed enrolment successful.
- Relay guidance recognises a running hosted service, and Chrome registration no longer prints a reporting hint.

## 0.4.9 (29 September 2026)

Upgrading: session logs are now written under an advisory lock. A host's MCP server started under 0.4.8 or earlier and still running after the update takes no lock; its writes stay whole as before, and restarting the host brings it under the lock.

### Added

- `commonmeasure relay --json` prints the run's session accounting, with each withheld session's directories and the rule that kept them on this machine, and each session skipped because its log did not read ([withheld sessions](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/telemetry-projection.md#withheld-sessions)).
- `commonmeasure session` says whether the session's crossings are cleared to leave under the policy now and, for those that are not, names the directory and the rule; `session --json` prints the same with the session's torn lines ([reading it](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/session-evidence.md#reading-it)).

### Changed

- A withheld session says why. `relay` prints one line per rule under "withheld": no scope selects the directory, the selecting scope does not set `allow_telemetry_egress: true`, directory selection leaves it out, or the scope failed closed, with the sessions' count and directories. `doctor` prints the last run's lines and `doctor --json` carries each session as `sessions.withheld` ([withheld sessions](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/telemetry-projection.md#withheld-sessions)).
- The reporting ruling's check that the relay would read a session's log reads only what was appended since the last ruling, one line at a time, so a long-lived session's fetches no longer slow and grow in memory with its log.

### Fixed

- A process killed while writing a session record no longer loses the session's evidence and reporting. The next write to the log, or the relay before it reads for delivery, terminates the cut-short line and records an `evidence_gap` naming its length, and every reader skips that line; any other line that does not parse still makes the log unreadable, and the error names the line. A write another process is still making is waited for, never cut ([reading a log](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/session-evidence.md#reading-a-log)).
- Inbound HTTP header values accept a tab between visible characters, as RFC 9110 allows; leading and trailing whitespace is trimmed as before. A tab in a publisher's response header no longer prevents the edge from reading `robots.txt` and fetching the page. Outbound header guards still refuse tabs and other control bytes.
- Host installation names the background relay step for every host without a session-end event, including Codex. After managed enrolment, macOS offers to install the relay at the terminal; unattended runs print the command. Other platforms name `relay --every 300`. `status` and `doctor` explain that these hosts refuse sources requiring usage reporting until an automatic relay runs.

## 0.4.8 (29 September 2026)

Upgrading: without reporting consent, sources whose licence demands usage
reporting are refused until you agree with `commonmeasure consent agree`. An
existing Edge home has no consent until you give it; a scope's
`allow_telemetry_egress` is not read as consent. `commonmeasure update` from
0.4.7 or earlier runs the installer of the release it replaces, which neither
asks for consent nor names the command: run `commonmeasure consent agree`
after that first update.

Upgrading: once a 0.4.8 policy synchronisation has accepted a managed revision, or been offered the applied one again, `managed/state.json` records the revision's organisation, which 0.4.7 and earlier cannot read. After a downgrade those releases report policy synchronisation as unavailable and keep enforcing `policy.json` unchanged; upgrade again to resume synchronisation. An edge moved from one organisation to another and back judges the first organisation's revisions afresh: an unexpired earlier revision from it is accepted, bounded only by the expiry that organisation's hub set ([re-enrolment](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/policy-envelope.md#re-enrolment)).

### Added

- `commonmeasure consent` shows the reporting consent and its text; `consent agree` and `consent withdraw` record the answer. The installer asks once, from the terminal, when the Edge home records no answer; `--agree-reporting` or `COMMONMEASURE_REPORTING_CONSENT=agree` agree without asking. The installer's closing line says what leaves under the answer recorded, a withdrawn answer included: uses admitted while consent was agreed are still reported.
- `status`, `doctor` (text and `--json`) and the console's Overview list the sources refused for want of reporting consent, each with its count, and the command that agrees.
- `hosted-service.json` takes `session_directory` again, an absolute directory every session of the hosted service is scoped to: a session resolves its policy as a local session in that directory would, records it as `cwd` on each crossing so the relay clears it by that scope, and writes a `hosted_scope` record naming the service configuration as its basis. A session whose declared directory no scope of the policy in force and no enrolled directory selects is not opened, and the answer names the directory. `status` and `doctor` say the scope, its engagement and whether it clears egress, that none is declared, or that nothing selects it ([hosted scope](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/session-evidence.md#hosted-scope)).

### Changed

- A licence's telemetry reporting demand is met under the operator's reporting consent, asked once at install and kept in `consent.json` in the Edge home, instead of a scope's `allow_telemetry_egress`. With consent the source is admitted in every scope, including one that sets `allow_telemetry_egress: false`; without it the source is refused in every scope, and the refusal names the source, says it needs reporting and gives the command that agrees. An unreadable `consent.json` is not consent and the refusal names its error. Nor is a symbolic link, a file owned by another user or a file writable by its group or others: the refusal names which, and `consent agree` and the installer write the file at mode 0600 whatever the umask. A demand is also refused, in every scope, where operator terms that require `access_context` for its host would make the relay hold its crossing, or where the session's log does not read, which the relay skips whole; the refusal names the log ([reporting consent](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/session-evidence.md#reporting-consent)).
- The relay sends a crossing admitted under reporting consent, its retrieval and grounding only, where the scope clears no egress; the session's turn boundaries, other crossings and refused count stay home unless the scope clears them. A withdrawal refuses the next fetch and recalls nothing: a crossing admitted before it is still reported. The relay's summary says how many projected sessions carry no refused count rather than adding them to the count as zero. Where operator terms for a host require `access_context`, the relay holds that host's crossings and sends the rest of the session as cleared, where it held the whole session before; its summary counts the crossings held, so a later crossing of the session, admitted or refused, cannot stop an earlier reported one from leaving ([telemetry projection](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/telemetry-projection.md#selected-coverage)).

### Fixed

- A managed edge re-enrolled into another organisation or under another signer accepts that organisation's first policy revision whatever its number, instead of refusing it as a rollback; until then the previous organisation's revision stays in force and `policy sync`, `connect`, `status` and `doctor` name the organisation it came from. Up to and including 0.4.1, `connect` stored a hub URL with credentials, and the hosted edge published them in its protected resource metadata, which needs no token, and in its 401 answer to any token naming another issuer, which includes every token the hub issued; its start line wrote them to the service journal, and `disconnect` and directory status printed them ([enrolment](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/enrolment.md#the-exchange)).

A licence reference sent to the telemetry receiver, including one already queued, no longer carries credentials from the URL of the page it was found for; up to and including 0.4.1 it did ([telemetry projection](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/telemetry-projection.md)). - A session's `edge_identity` record names the hub by its origin alone (scheme, host and port), or `null` where the stored hub URL has none, and the console's Agents view and `GET /api/sessions/<id>` reduce a record written by an earlier version to its origin when they read it; session logs are not rewritten. Up to and including 0.4.1, the record held the hub URL as stored; where 0.4.1's `connect` stored one with credentials, every session record held them, and the Agents view and the session records API showed them. The session records API also reduces a `policy_sync` record's policy URL to its origin, because 0.4.1 built that URL from the stored hub URL where the hub gave a policy path and no policy URL; up to and including 0.4.1 the API served it whole ([session evidence](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/session-evidence.md)).

Session logs are not rewritten. From 0.3.1 up to and including 0.4.1, a name resolution that did not finish within the budget (3 seconds at session start) and a refused `policy_url` recorded the policy URL whole, with any credentials in it, in the session log's `policy_sync` reason, the timeout also in the managed state file, and `status --json` and the console showed it: the console's session records API, record page and Agents view, to anyone who could reach it. If a `policy_url` in your `deployment.json` held credentials, revoke that credential on the hub and remove it from the file ([session evidence](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/session-evidence.md#policy-synchronisation)).
- Up to and including 0.4.1, the relay wrote `relay/receipts.json`, `session-agents.json`, `refused-delivered.json` and `skipped-sessions.json` under the umask, so under the usual `022` any local user who could reach the home could read them, and a leftover `<file>.json.tmp` passed its own mode on. `receipts.json` holds the receiver URL last delivered to, with any key in its credentials or query. Each file becomes owner-only at its next write; `receipts.json` at the next delivery attempt. If your receiver URL carries a key and other local users can reach the home, run `chmod 600 ~/.commonmeasure/relay/*.json` (or the same files in your Edge home) now, delete any `relay/*.json.tmp`, and rotate the key.

## 0.4.1 (25 September 2026)

**Upgrading:** 0.4.1 upgrades from 0.4.0 only. It refuses a relay spool that
holds `relay/spool/outbound.ack` or queue lines without an index, which 0.3.4
and earlier wrote, and sends nothing from it. On such a home:

1. Stop every relay, including `commonmeasure hosted service`
   ([one release per Edge home](https://github.com/commonmeasure/commonmeasure/blob/main/ARCHITECTURE.md#what-runs-where)).
2. Upgrade.
3. Run `commonmeasure status` and read its `refused spool` line
   (`egress.refused_spool` with `--json`): how many indexed batches are still
   queued or dead, and whether that count is complete.
4. Move `relay/spool` aside, keeping it and `relay/delivered.idx`.
5. Run `commonmeasure relay` without `--session`, or restart the hosted
   service, whose interval run does the same. It projects outstanding events
   again from every session log under `sessions/`, under the approvals and
   policy in force, and queues no event that `relay/delivered.idx` records as
   accepted. The one exception is an event resent under its own id to carry a
   session's changed refused count. Pass `--run` again for each published run
   whose events were outstanding.

An outstanding event whose session log or run input is gone is not projected
again: it stays in the saved spool, undelivered
([delivery state](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/telemetry-projection.md#delivery-state)).

### Added

- Reported telemetry now includes `data.commonmeasure-crawl-delay` on mediated retrievals with a recorded, honoured `Crawl-delay` above zero, capped at 60 seconds; it is absent when that evidence is missing ([telemetry projection](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/telemetry-projection.md)).

### Changed

- The edge reports its release with every directory proof, and the hub leaves a key unlisted when the last accepted upload reported no release or one below its floor. Upgrade the edge to at least the hub's floor: the key stays unlisted until that edge uploads a proof. After an upgrade, the edge uploads on its next relay run; a failed upload due only to the release change waits an hour before another attempt ([enrolment](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/enrolment.md)).
- Failing hosts put later mediated requests into back-off, shared across sessions and restarts on one edge: 429 and 503 honour a usable `Retry-After` up to one hour; other 5xx responses, and 429 or 503 without a usable header, start at 10 seconds and double for consecutive failure periods up to 15 minutes. Failed requests are never resent automatically; later requests wait within their remaining budget or are refused, and one sender goes first after back-off ends ([failure policy](https://github.com/commonmeasure/commonmeasure/blob/main/docs/FAIL-POLICY.md)).
- Hosted back-off refusals say only that the host is in back-off, except that they may give the end when the host supplied it as an uncapped `Retry-After` HTTP-date; other tenants' response status, failure count and timing remain private ([session evidence](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/session-evidence.md)).

### Removed

- The relay no longer imports acknowledgements from `outbound.ack` or reads
  a queue line by its position. It refuses such a spool and names the file
  or line and the remedy; `status` and `doctor` say how many batches in its
  indexed lines are still queued or dead, and whether that count is complete
  ([delivery state](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/telemetry-projection.md#delivery-state)).
- A queued batch without `directory_selection` is no longer sent as if no
  directory selection applied: the line is reported as damaged. An
  undelivered batch that 0.3.4 or earlier queued is held and never sent
  ([directory enrolment](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/directory-enrolment.md)).
- `doctor` no longer reads a `relay/receipts.json` that names no accepting
  receiver as a delivery to the configured one; it says the file is from
  0.3.4 or earlier and that the next delivery rewrites it.
- The fleet-status classifier no longer compares an edge that reports no
  envelope digest (0.3.0) on its loader digest; it reads as `unknown`
  ([fleet status](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/fleet-status.md#what-a-receiver-concludes)).

### Fixed

- Directory-proof failures retain non-JSON error bodies up to 2 KiB on a character boundary, with a truncation marker giving the original byte count; JSON `detail` and `message` strings remain whole ([enrolment](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/enrolment.md)).
- Telemetry receivers can acknowledge a batch with any `2xx` response, including an empty body; when the response supplies no valid count of newly recorded events, the relay reports that count as unknown ([receiving reports](https://github.com/commonmeasure/commonmeasure/blob/main/docs/integrate/reports.md)).
- A relay run uses the reporting approvals it has just refreshed, so an approval renewed after expiry allows reporting during that run without a separate enrolment sync ([telemetry projection](https://github.com/commonmeasure/commonmeasure/blob/main/docs/contracts/telemetry-projection.md)).

## 0.4.0 (23 September 2026)

`robots.txt` now binds in every policy mode. An operator who ran `observe`
or `prefer` and relied on the edge fetching a disallowed page will see that
crossing refused.

### robots.txt

- A `Disallow` addressed to `CommonMeasureBot`, or to `*` where no group
  names it, refuses the crossing before the page is fetched in every policy
  mode: `strict`, `observe` and `prefer` alike. In earlier releases
  `observe` and `prefer` fetched the page and recorded the rule.
- A `robots.txt` that cannot be read follows RFC 9309 §2.3.1 in every mode.
  A 4xx other than 429 means no rules. A 429, a 5xx, a timeout, or a name,
  TLS or connection failure means unreachable: the last answer the host
  gave rules, however old; with none held, the crossing is refused as a
  complete disallow. A failed probe never replaces the last answer held.
- A `robots.txt` larger than 512 KiB is parsed up to its last complete line
  within that bound (RFC 9309 §2.5), and the record carries `truncated` with
  the file's size and the bytes read. Earlier releases discarded an
  oversized file and fetched with no rules, so padding the file switched its
  `Disallow` off.
- A `robots.txt` redirect the edge declines to follow (to an address it does
  not mediate, to the hub's origin, or to a host the operator's policy
  refuses) counts as unreachable. More than five redirects is unreachable.
- A robots refusal names the source's `robots.txt`, not the operator's
  policy file. The record carries the address of the file that ruled, so a
  redirected `robots.txt` is named by where it was read from.
- A `robots.txt` request that the edge cut short (the call's time limit left
  no time for it, or it could not be signed) refuses the crossing in every
  mode and is not held as the host's failure.
